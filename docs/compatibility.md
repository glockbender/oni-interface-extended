# Compatibility review

Static source review, 2026-10-16, against Interface Extended 1.3.0 source. No other mods were installed or run for this review. **No pairwise incompatibility is confirmed.** This is a shortlist for later testing, not a list of supported or blocked mods. Public repository source can differ from the version delivered by Steam.

## Where interactions can occur

Interface Extended changes the horizontal anchors of nine named children of `GameScreenManager.ssOverlayCanvas` and the overlay-level ancestor of `DetailsScreen`. It discovers roots periodically and applies the width in `LateUpdate`. It preserves current offsets, sizes, vertical anchors, parents and sibling order. Children of those roots normally move with them; unrelated direct children of the canvas are not automatically centered.

The settings entry is a postfix on `OptionsMenuScreen.OnPrefabInit`; installation of the controller is a postfix on `GameScreenManager.OnSpawn`. The settings window clones native controls, uses a modal `KScreen` and a canvas with sorting order 1000, temporarily hides the native options panel by changing its scale, and owns one pause request. Optional shortcuts read Unity input directly and are disabled by default.

These are the relevant conflict classes:

| Shared surface | Possible failure | Assessment |
| --- | --- | --- |
| Same root anchors | Another layout controller can overwrite our anchors later in the frame, or our mapping can change its intended coordinates. Relative adjustments can compound. | Highest-priority class to test if such a mod is present; no named anchor-writing conflict was established in the sources below. |
| Offsets, parent changes or replacement panels | Saved offsets can combine with the centered region; a new direct canvas child can remain at the edge. A root reparented after discovery is still in our tracked list. | Partial visual integration is possible without an exception or Harmony conflict. |
| Native options list or prefab replacement | A later patch that replaces the entire button list can remove our entry; renamed/replaced template objects can break our hierarchy lookups. Cloning a modified prefab also copies third-party components. | Shared method names alone do not establish a conflict. The current insertion copies and preserves existing entries. |
| Modal/input/rendering | Separate Unity input polling can act even when a `KButtonEvent` is consumed. Another modal can have different sorting or pause ownership. | Leave shortcuts disabled unless needed; verify focus, Escape, click blocking and pause restoration together. |
| Increased child content size | Extra management buttons or wider side screens can overlap within a narrow region. | Layout constraint, not necessarily incompatible code; a wider HUD can be sufficient. |

## Practical guidance and follow-up

Do not block a mod by name or add speculative Harmony ordering rules from this review. A second postfix on the same method can coexist; actual replacement logic and ordering determine the outcome. Ordering Harmony startup patches also does not order separate Unity `LateUpdate` methods.

For a later check, load a copy of the dedicated baseline test save with the exact game build and mod versions recorded. First test Interface Extended alone, then add one relevant mod at a time. Compare full width, 3360 and 2560 using the same paused camera. Include expanded/collapsed right-hand sections, lazy selection details, added management buttons, tooltips, settings open/close and initial paused/playing states. Capture screenshots and measured root rectangles as described in [testing.md](testing.md).

If a problem appears, select **Full width** first. This restores our anchor mapping while leaving Interface Extended loaded, which helps distinguish layout interaction from settings-window/patch problems. For DraggableUI, also reset affected saved positions through that mod's controls. Record whether the symptom survives a restart and whether disabling either mod alone resolves it before reporting a pair as incompatible.
